# План превращения digest в десктопное приложение

Читай этот файл перед тем, как предлагать архитектурные решения или новые библиотеки.
Если твоя идея есть в разделе «Отклонено» — не предлагай её снова, вопрос уже закрыт.

## Кто пользователь

Коллеги-журналисты, не программисты. Установил, ввёл свои данные в окне, нажал кнопку.
Никакого редактирования .py, никаких батников, никакой консоли.
Руками человек делает только две вещи: ставит LM Studio и входит в свой Telegram.

Сообщения об ошибках пиши для такого человека: что случилось и что сделать.
Трассировка в лог, человеку — обычная фраза по-русски.

## Железные требования к дистрибутиву

- Ни одного моего ключа в сборке: ни api_id, ни api_hash, ни токена бота, ни chat_id.
- Ни моего state.json, ни моего файла сессии, ни моей памяти по id каналов.
- У каждого пользователя свой аккаунт Telegram, своя сессия, своё состояние.
- Список каналов и текст интересов могут ехать в сборке как заготовка по умолчанию.

## План шагов

Каждый шаг — отдельное задание с отдельным тестом. Не забегай вперёд.

1. Настройки вне кода: core/channels.py, core/settings.py, settings.json, interests.txt.
2а. Пути и блокировка: core/paths.py на platformdirs, лок на portalocker.
2б. Логи: loguru вместо core/logs.py с его _Tee и _prune. Печать — в события,
    чтобы окно могло показывать прогресс. Плюс флаг отмены прогона.
3. Адрес и имя модели из настроек в llm.py плюс скелет окна PySide6.
4. Визард входа в Telegram: номер, код подтверждения, пароль 2FA, кнопка «Выйти».
    Плюс автосоздание приватного канала для доставки через CreateChannelRequest.
5. Экраны настроек: таблица каналов со статусами, редактор интересов,
    проверка модели, глубина в часах.
6. Сборка: PyInstaller --onedir плюс Inno Setup, проверка чистого первого запуска.
7. Расписание через schtasks.

Перенос якорей id каналов из раздела __ids__ в записи каналов — отдельным шагом
после шагов 1 и 2. Сам его не начинай.

## Одобренные библиотеки

- platformdirs — путь к данным пользователя в %LOCALAPPDATA%.
- portalocker — блокировка от двойного запуска.
- loguru — логи с ротацией, переживает sys.stdout равный None в сборке без консоли.
- keyring — секреты в Диспетчере учётных данных Windows.
- PySide6, PyInstaller, Inno Setup — интерфейс и сборка.

Новые зависимости сверх этого списка — только через отдельный вопрос ко мне.

## Отклонено, не предлагать снова

- qasync и QtAsyncio — берём рабочий поток со своим циклом asyncio.
- pydantic-settings — избыточно для одного файла настроек.
- Готовые проекты с GitHub (tgcf, teledigest и подобные) — рассмотрены и отклонены.
- Смена модели или переход на облачную LLM по умолчанию.
- Доставка постов в Избранное (чат me).
- pywin32 для расписания — вместо него schtasks.
- tufup и любое автообновление — не раньше шага 7.

## Чего требует интерфейс от логики дайджеста

Это пригодится на шагах 3 и 5, но знать об этом надо раньше, чтобы не загнать себя в угол.

- Прогон идёт в рабочем потоке, окно не должно замирать.
- Прогресс виден человеку: какой канал сейчас, сколько проверено, сколько отобрано.
- Прогон можно отменить кнопкой, и отмена не должна терять посты:
  курсор остаётся на последнем успешно отправленном.
- Каналы из списков renamed и unreachable получают пометку в таблице и кнопку
  «Обновить ссылку». Молча править ссылку нельзя — только с видимым уведомлением.
- Ссылка проверяется сразу при добавлении канала, а не на первом прогоне.
- Страховка от смены ника работает только для каналов, чей id уже запомнен.
  Для только что добавленных она не сработает, и это нормально.
- Приложение никогда не правит свой исходный код. Всё изменяемое — в файлах настроек.

## Как со мной работать

- Один шаг — один тест. Увидел соседнюю проблему — скажи о ней и жди решения.
- Перед каждым шагом — git commit.
- Боевой прогон без --dry-run запускаю только я, и только вручную.
- Ошибся в диагнозе — скажи сразу, не доводи неверную версию до конца.
- Считаешь правку бесполезной — так и скажи, не делай её из вежливости.
